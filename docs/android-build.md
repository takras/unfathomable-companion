# Android build

The Android app can be built two ways: on GitHub Actions (`.github/workflows/android.yml`, no local
tools needed) or locally with Android Studio's SDK and JDK through the `npm run android:*` scripts.

## On GitHub Actions

Actions → **Build Android app** → Run workflow, and pick a target:

| Target      | Produces                                                   | Needs              |
| ----------- | ---------------------------------------------------------- | ------------------ |
| `debug-apk` | `UnfathomableCompanion-<version>-debug.apk`                | Nothing            |
| `release`   | `UnfathomableCompanion-<version>.aab` and a signed `.apk`  | The secrets below  |

Both land in the run's artifacts (kept 14 days). The debug APK installs directly on a phone (allow
installing from unknown sources) or an emulator. The `.aab` is what Google Play takes.

Manual trigger only, like the iOS build. Linux runner minutes are cheap, so a push trigger could be added
later if wanted.

## Versions

From `package.json`, as in `android/app/build.gradle`: `versionName` = `1.2.3`, `versionCode` = `10203`
(major·10000 + minor·100 + patch), the same scheme as the iOS build number. Google Play rejects a
`versionCode` it has seen before, so bump with `npm version patch|minor|major` before each upload.

## Signing (release)

Google Play uses **Play App Signing**: Google holds the app signing key, and you sign uploads with your
own **upload key**. Create it once and back it up somewhere safe; losing it means asking Google for a
reset.

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

`*.jks`, `*.keystore` and `keystore.properties` are git-ignored; never commit them.

### For GitHub Actions

Repository secrets (Settings → Secrets and variables → Actions):

| Secret                      | Value                                              |
| --------------------------- | -------------------------------------------------- |
| `ANDROID_KEYSTORE_BASE64`   | The `.jks` file, base64-encoded (see below)        |
| `ANDROID_KEYSTORE_PASSWORD` | The keystore password                              |
| `ANDROID_KEY_ALIAS`         | The key alias (`upload` in the command above)      |
| `ANDROID_KEY_PASSWORD`      | The key password                                   |

Base64 of the keystore, as one line:

```bash
base64 -w0 upload-keystore.jks
```

(On Windows PowerShell: `[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-keystore.jks"))`.)

The workflow writes the keystore to the runner's temp folder, passes it to Gradle through the
`UNF_KEYSTORE_FILE`, `UNF_KEYSTORE_PASSWORD`, `UNF_KEY_ALIAS` and `UNF_KEY_PASSWORD` variables, and
deletes it after the build. A release build without signing stops with an explanation instead of
producing an unsigned bundle Play would refuse.

### Locally

Copy `android/keystore.properties.example` to `android/keystore.properties` and fill it in (or set the
`UNF_*` variables). Then:

```bash
npm run android:release   # signed App Bundle: android/app/build/outputs/bundle/release/app-release.aab
npm run android:debug     # debug APK: android/app/build/outputs/apk/debug/app-debug.apk
npm run android:install   # debug build installed on a connected phone or running emulator
npm run android           # open the project in Android Studio
```

`scripts/gradle.mjs` runs Gradle with Android Studio's bundled JDK and SDK unless `JAVA_HOME` /
`ANDROID_HOME` are set (some standalone JDKs on PATH reject `gradlew.bat`'s empty `-classpath`).

## Google Play

The app id is **`net.takras.unfathomable`**. Create the app in the Play Console first, then upload the
`.aab` to a testing track. Play also asks for a privacy policy URL:
**https://unfathomable.takras.net/privacy.html** (the app collects no data; also linked from About & licences).

## How the pieces fit

- **Icons and splash** – generated by `npm run icons` (Mother Hydra, from `scripts/icon.mjs`) into
  `android/app/src/main/res` (committed), including the adaptive icon's foreground and background layers.
- **Edge-to-edge** – Capacitor's SystemBars plugin (`capacitor.config.ts`) draws the app under the
  status and navigation bars and hands their sizes to CSS as `--safe-area-inset-*`; `src/styles.css`
  combines them with iOS's `env(safe-area-inset-*)` as `--sa-*`.
- **Saved games** – mirrored into Capacitor Preferences, since Android may clear a web view's storage.
- After changing web code, run `npm run cap:sync` (the `android:*` scripts do it) before building natively.
